# API-контракт

Машинный контракт описан в `contracts/main.tsp` и генерируется в `contracts/openapi/openapi.json`; клиентский SDK генерируется в `apps/frontend/src/api/generated`. Этот ADR фиксирует rationale и правила, а не заменяет TypeSpec-контракт.

Бэкенд — единственный источник Типов встреч и Броней; Брони хранятся в памяти процесса и сбрасываются при рестарте. Все ответы API, кроме служебного `GET /reserve`, отдаются как JSON с `Content-Type: application/json; charset=utf-8`.

## Эндпоинты

| Метод | Путь | Успех | Ошибки |
| --- | --- | --- | --- |
| `GET` | `/meeting-types` | `200` — массив Типов встреч | — |
| `POST` | `/meeting-types` | `201` — созданный Тип встречи | `400`, `409` |
| `GET` | `/meeting-types/:id/slots` | `200` — массив свободных Слотов | `404` |
| `GET` | `/bookings?upcoming=true` | `200` — массив предстоящих Броней | — |
| `POST` | `/bookings` | `201` — созданная Бронь | `400`, `404`, `409` |

`GET /reserve` — служебная проверка живости процесса: `200 text/plain` с телом `Reserved`. Она не относится к домену Броней и сохраняется для существующих smoke-проверок.

## Формы JSON

Тип встречи:

```json
{
  "id": "c0a8014e-7c1e-4a8f-9c3a-1b2d3e4f5a6b",
  "title": "Консультация",
  "description": "Обсуждение проекта",
  "durationMinutes": 45
}
```

- `id` — UUID, генерируется бэкендом.
- `durationMinutes` — одно из значений `15`, `30`, `45`, `60`; остальные значения отклоняются с `400`.

Слот:

```json
{
  "startsAt": "2026-01-05T09:00:00+03:00",
  "endsAt": "2026-01-05T09:45:00+03:00",
  "isAvailable": true
}
```

Бронь:

```json
{
  "id": "4b9f8a2c-1d3e-4f5a-8b6c-7d8e9f0a1b2c",
  "meetingTypeId": "c0a8014e-7c1e-4a8f-9c3a-1b2d3e4f5a6b",
  "startsAt": "2026-01-05T09:00:00+03:00",
  "guestName": "Анна",
  "guestEmail": "anna@example.com",
  "createdAt": "2026-01-05T05:12:34.000Z"
}
```

- Все идентификаторы — UUID.
- `startsAt`, `endsAt` и `createdAt` — ISO 8601. Время встреч и Слотов передаётся с московским смещением `+03:00`; `createdAt` — момент создания в UTC (`Z`).
- `GET /bookings` возвращает ровно модель Брони, без `meetingTypeTitle` и других вычисляемых полей. Клиент сам сопоставляет `meetingTypeId` с загруженным списком Типов встреч.
- `GET /bookings?upcoming=true` возвращает только Брони с `startsAt >= сейчас`; без параметра возвращается полный список. Страница владельца использует upcoming-режим.
- `POST /bookings` принимает `{ meetingTypeId, startsAt, guestName, guestEmail }`; `startsAt` должен совпадать со свободным Слотом выбранного Типа.

## Ошибки

Тело ошибки всегда имеет вид:

```json
{ "error": "Текст ошибки на русском" }
```

- `400` — некорректный JSON, тело больше лимита, невалидные поля или `startsAt` вне доступной сетки Слотов.
- `404` — неизвестный Тип встречи или несуществующий маршрут.
- `409` — выбранный Слот пересекается с уже существующей Броней или Тип встречи с такой длительностью уже создан.

Лимит тела JSON-запроса — 1 МиБ (`1024 * 1024` байт). Превышение и битый JSON возвращают `400` с `{ "error": "…" }`, а не `500`.

## Внутренние опции `createServer()`

`now`, `staticDir`, `apiPrefix` и `allowTestReset` — внутренние параметры сборки сервера, а не часть публичного API:

- `now` позволяет тестам зафиксировать текущее время.
- `staticDir` включает раздачу собранного фронтенда для не-API GET/HEAD-запросов.
- `apiPrefix` нормализует префикс `/api` в production.
- `allowTestReset` включает тестовый `POST /__test__/reset` (в dev через Vite — `/api/__test__/reset`), который очищает Типы встреч и Брони и возвращает `204`. В обычном запуске эндпоинт отсутствует и отвечает `404`.
