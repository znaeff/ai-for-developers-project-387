# Правила расписания и Слотов

Расписание одно на всего Владельца: Пн–Пт, 09:00–18:00 по поясу `Europe/Moscow` (UTC+03:00, без перехода на летнее время). Выходные исключены. У Владельца один календарь, поэтому Брони **всех** Типов встреч занимают общие Слоты.

## Кандидаты и окно

- Кандидаты на начало Слота идут каждые 15 минут, начиная с 09:00.
- Встреча длительностью `durationMinutes` должна целиком помещаться до 18:00: подходят только старты, для которых `start + durationMinutes <= 18:00`.
- Длительность выбирается только из фиксированного списка: 15, 30, 45 или 60 минут.
- Показываются только будущие Слоты (`start > сейчас`) в окне до 14 дней (`start < сейчас + 14 дней`).

## Пересечение интервалов

Занятость считается по полуинтервалам: встреча занимает `[startsAt, endsAt)`, и два интервала пересекаются, если `left.startsAt < right.endsAt && right.startsAt < left.endsAt`. Одинаковый предикат используется и при генерации Слотов, и при проверке конфликта в `POST /bookings`.

`busyIntervals` строит занятость по каждой Брони с длительностью её собственного Типа встречи. Поэтому Бронь Типа A делает недоступными пересекающиеся Слоты Типа B, даже если Типы имеют разную длительность.

## Пример с 45 минутами

До бронирования у 45-минутного Типа кандидаты могут пересекаться: 09:00–09:45, 09:15–10:00, 09:30–10:15, 09:45–10:30 — все валидные старты 15-минутной сетки.

После Брони 09:00–09:45:

- Слот 09:00 остаётся в выдаче с `isAvailable: false`;
- Слот 09:15 остаётся с `isAvailable: false`, потому что 09:15–10:00 пересекается с занятым 09:00–09:45;
- Слот 09:30 остаётся с `isAvailable: false`, потому что 09:30–10:15 пересекается с занятым 09:00–09:45;
- следующий свободный Слот — 09:45–10:30.

Это же правило действует для Броней других Типов: если 45-минутная Бронь Типа A занимает 09:00–09:45, то у 30-минутного Типа B Слоты 09:00, 09:15 и 09:30 будут с `isAvailable: false`, а `POST /bookings` на 09:30 вернёт `409`.

## Отклонённые альтернативы

- Отдельный календарь на каждый Тип встречи — отклонён: у Владельца один физический календарь, и параллельные встречи невозможны.
- Хранение Слотов в базе — отклонено: Слоты детерминированно вычисляются из расписания, длительности Типа и занятых интервалов.
